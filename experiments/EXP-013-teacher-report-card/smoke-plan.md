# EXP-013 冒烟计划（PRINCIPLES §1 三步验证：先最小，再体量，再分辨力）

在起跑全量（4200 局）之前，用 1 条 workflow 的两个小 job 买三样东西：

## 1. 熔断测试（build job 内，1 局，超时 150s）

`--trainer mcts --mcts-stages all --mcts-search-n 64 --mcts-selection pt --plans 1 --runs-per-plan 1`

- 证的是"全阶段 sn64 单局能在 CI 单核预算内跑完"这一件事，不出任何分数结论。
- 挂了 = 全量 1 小时预算不成立，就地止损，不浪费 bench 矩阵。

## 2. 耗时标定（smoke job，5 计划 × 8 局 = 40 局，~3–5 分钟）

`smoke_read.py` 输出单局 mean/p50/p95 → 外推全量：
- 单臂 CPU·h = mean_ms × 4200 / 3.6e6
- 每片墙钟 = 单臂 / 6 分片 / 4 vCPU（runner 核数）

对照 bench job timeout 150min 判安全/需加分片。**外推值仅供预算校准，不进任何台账分数**。

## 3. 手写路径未坏（smoke job 附带）

手写 base 臂 5×8 冒烟应秒级完成且无异常——013 补丁改了 bench CLI 与 run_plan，
虽然三个手写臂的代码路径一字未动，仍要实证"没碰坏"。

## 4. 分辨力（不放 smoke，放 full 的锚点里）

协议能测出已知差异的证据 = 三保真锚逐位复现（65438.2 / 65554.2 / 66734.8）+
NN 臂与深教师臂同种子配对差远超其 SE。锚点破位即全实验作废（verdict.py 硬断言）。

## 判据（不满足就不进 full）

- 熔断 1 局 < 150s
- 冒烟 40 局全部完成、自选未达标计数正常打印
- 外推每片 < 100 min（150 min 超时留 1/3 余量）
- 手写冒烟分数与 65438.2 锚在统计噪声内（n=40 只有方向性，看数量级不看尾数）
